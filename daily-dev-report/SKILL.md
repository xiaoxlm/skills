# 每日开发进度日报

自动整合 git 提交记录与用户补充，生成结构清晰的中文日报。

## 工作流程

### 1. 收集信息

自动获取“今日 + 指定作者”的 git 提交（默认排除 merge）：

```bash
git log --since="$(date +%Y-%m-%d) 00:00:00" --until="$(date +%Y-%m-%d) 23:59:59" --author="<作者名>" --oneline --no-merges 2>/dev/null
```

作者名规则：
- 用户明确给出作者名（如 `oscar_xlm`）时，必须严格使用该作者过滤
- 用户未给出时，先询问作者名；若用户不在意再放宽为“当前仓库作者”

若无记录，fallback：`git diff --stat HEAD~1 HEAD 2>/dev/null | head -20`

若 git 仍不足以反映今日工作，优先从当天编写的代码中分析；实在无法推断再询问用户补充。

### 2. 按模板生成日报

```
**日期：** YYYY年MM月DD日（周X）

**今日完成**
- [动词开头，描述工作项]

**遇到的问题**
- [问题] → [解决方案/当前状态]
（若无写：无）

**价值体现**
- [为公司/用户/团队/其他 带来的具体价值]

**备注（可选）**
```

## 价值体现的写法

每条不要只写动作，要体现背后的价值。写之前先想清楚：修复/优化的是具体什么问题？复杂度如何？带来了什么可见提升？

**三种文案思路：**

1. **动作 + 对象 + 价值** — 说清你救了谁、省了什么（时间/成本/资损）
2. **体现复杂度** — 用前缀凸显排查难度：定位并解决了… / 排查并修复了… / 复现了极低概率的… / 经过多轮压测验证…
3. **量化对比** — 用数字说话，让成果可视化

**示例：**

| git commit                   | 日报描述                                                      |
| ---------------------------- | ------------------------------------------------------------- |
| `fix: 修复了一个登录 bug`    | 修复了登录页面偶发闪退问题，提升了用户登录成功率              |
| `fix: 数据导出偶尔报错`      | 排查并解决了高并发下导出导致的 OOM 问题，优化了导出逻辑       |
| `perf: 优化用户信息查询接口` | 为用户查询接口添加 Redis 缓存，接口响应时间从 1.2s 降至 300ms |

## 输出规则

- 合并同类 commit，不逐条罗列；英文内容转为中文表达，技术术语可保留（API、Redis、PR）
- 每项 1-2 行，简洁专业
- 默认直接在对话中输出日报内容，不自动创建或写入本地文件
- 仅当用户明确要求“保存/落盘/写入文件”时，才输出成 Markdown 文件（默认路径可用 `dailywork/年月日.md`）
- 生成内容必须只基于过滤后的作者提交，不混入其他作者内容
- 信息不足时用 `[待填写]` 占位，并在备注中提示补充
